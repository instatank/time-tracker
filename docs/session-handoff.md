**2026-08-17 (branch `claude/security-detector-check-screen-42m4ke`, APP CODE — SW bumped `dayos-v138` → `dayos-v139`):** shipped **Phase 1** of `docs/security-audit.md` — the secret detector *and* the read-only **Settings → Security check** screen, in one PR. This partially closes gap **S1** (*at rest* is now covered; at-input / at-save / pre-AI-send remain Phase 3).
- **Detector:** pure `scanText(text) -> [{kind, category, masked, line, start, end}]` in `index.html`, fenced between `// ── BEGIN secret-detector ──` / `// ── END secret-detector ──` so the sims extract the *shipped* source, not a copy. `category` is `shaped` or `worded` — the two tiers the doctrine says to tune separately. `masked` is first 4 + last 2 chars only, ≤6 chars hidden entirely; shaped matches are masked **in place** inside the `line` field, so a shaped secret never appears in full in any field. The Firebase Web API key is a hardcoded exception (public by design, ships in the page).
- **Tuned for SENSITIVITY, on purpose** — this surface is read-only and batch-reviewed, so a false positive costs one glance and a miss costs a credential. That is deliberately the opposite of `.gitleaks.toml`, which blocks a merge. Don't "fix" a noisy worded rule by tightening it without re-reading the doctrine section.
- **Three tuning decisions carry the weight:** worded keywords need an `is`/`was`/`:`/`=` immediately after the word (this is what keeps "need to reset my password" off the screen); high-entropy runs exclude `-`/`_` (so slugs, `default-<tpl>-<date>` block ids, UUIDs and `dayos_*_v1` keys never qualify) and reject hex (git SHAs); base64 inside `data:` URIs is suppressed, or every pasted screenshot would be a finding.
- **Screen:** sweeps blocks, captures, daily journals, sessions, learning, EOD, DFTs, weekly + monthly reviews — **including trashed entries**, voice-note titles and attachment filenames. Grouped by category (shaped first), newest first; each row = type · date · masked match · surrounding line, tap to open. Header states the scanned count, that nothing was sent, and that it does **not** reach the second-brain mirror or the `2ndbrain` repo.
- **Zero writes / deletes / network — a hard constraint, not an aspiration.** Nothing is persisted, not even the scan result. Two routing decisions protect it: a **trashed** finding opens Settings → Trash rather than the entry editor (those editors autosave, so that would have been a write path), and machine-generated fields (`url`, `storagePath`, ids) are never scanned — a Storage download URL embeds a 28-char uid, so walking them would flag every attachment forever.
- **Two new sims, both in `scripts/check.sh`:** `tests/security-detector.mjs` (corpus of **34 true positives / 49 true negatives** from real DayOS shapes — hashtags, `uid()` ids, Firestore doc ids + paths, git SHAs, IST timestamps, base64 image data, the Firebase key, and sentences that merely *mention* a password) and `tests/security-screen.mjs` (all nine collections swept, trash covered, HTML escaped not executed, no raw secret in the markup, and **zero calls** to trapped `localStorage`/`fetch`/`setDoc`/`saveLocal`).
- **`.gitleaks.toml` gained two path allowlist entries** for those corpus files — verified locally with real gitleaks 8.28.0: 19 findings before, `no leaks found` after, and `index.html` was clean throughout. Cost stated in the config: a real secret pasted into either file would not be caught, so they must hold fabricated values only.

## Branch flow + deploy (CRITICAL — read before touching Vercel)

- **`claude/*` → auto-merges to `main` → Vercel deploys.** Every commit ships.

## Conventions you must follow

- **One file is the app:** `index.html`. No build step, no `package.json`. CLAUDE.md has the full architecture rundown.
- **IST helpers only.** Never `new Date()` directly — use `nowIST()`, `nowISTIso()`, `todayStr()`, `capDateIST()`, `addDays()`. Direct `Date()` causes silent timezone drift.
- **Sync writes need 3-site wiring.** New collection → per-write sync function + `forcePushToCloud` + `forcePullFromCloud` + `initialSync`. Miss any and cross-device data is lost silently.
- **Tombstones for any list where users delete.** `_synced` flag for any per-item write. Both patterns are already in use; mirror them.
- **Soft-delete via `deletedAt: ISO`** for entries the user can recover from Trash. Hard-delete via the existing tombstone+cloud path is reserved for the 7-day sweep.
- **Inline-handler reachability:** module-scope functions referenced by `onclick=""` must be on `window`.
- **Use function-wrapper aliases, not bare assignments.** `window.X = function() { window.Y(); }` not `window.X = window.Y`. The latter captures `undefined` if Y is defined later in the file. Got bitten earlier — see commit `9e107fb` for the fix pattern.
- **Bump `dayos-vN` in `sw.js` on every user-facing change.** Server-only changes (`api/*.mjs`) don't need a bump.
- **iOS PWA: use `min(env(safe-area-inset-*), Npx)` patterns** when capping. `max(env(...), Npx)` for forcing a minimum.
- **Docs drift independently of each other.** Reconciling `session-handoff.md` does NOT mean `CLAUDE.md` (or vice versa) is current — each doc describing the same system must be checked against the actual code separately, every session. A doc's own "reconciled [date]" header is not proof it's accurate; verify, don't trust the label.
